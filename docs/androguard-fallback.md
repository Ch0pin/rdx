# Experimental optional Androguard source fallback

Every nonempty alternate method returned for an exact native-failed DEX ID is shown as **Unverified Androguard reconstruction**, rendered in red. Directly below the warning is a collapsed **Original DEX** row; expanding it reveals the method ID, native failure reason, DEX link and Androguard diagnostics above that exact original method. The reconstructed method follows the row. Context, placeholder and malformed-Java observations are visible diagnostics; they do not suppress available output or establish semantic correctness.

The fallback is off by default. Enable it in View → Settings → Androguard fallback to refresh the current source view automatically. Classes opened from search results use the same browsing policy automatically. Search matches are relocated only through exact preserved source spans. A match inside original DEX keeps its row collapsed until the user expands it; an unmapped match opens at class start with an explicit note. Internal folding markers are hidden from the code view and clipboard output. The optional release helper is discovered beside the RDX executable or through the absolute `RDX_ANDROGUARD_HELPER` environment variable. Hover over the Androguard fallback setting for availability, behavior, timeout and executable path.

RDX renders the class first and retains successful native methods. Failed methods are matched by original owner, name, parameters and return descriptor, including constructors, overloads and class initializers. Alternate methods retain the native reason/status, backend version and quality diagnostics. Their exact original DEX is stored once in a byte-length tagged block; folding preserves the full source and Unicode mappings. Neither the alternate body nor preserved DEX receives guessed source/xref links. `native_counts` retains native reconstruction results, while `counts` describes displayed representations. Search/index and bulk export stay native.

The helper is the pure Rust `androguard/dex-decompiler`, pinned to `f7fa4a4853d957ebc3c54355d128a3835ef5ae22`. Its dependencies are vendored at exact revisions, with one source modification preserving fully qualified names. Build instructions and protocol details are in `/Users/ch0pin/Desktop/Git-Projects/rdx/tools/androguard-helper/README.md`; pins, source-change hashes, license inventory and MPL source are in `/Users/ch0pin/Desktop/Git-Projects/rdx/third_party/androguard`.

One short-lived process receives the owning DEX, slices one class and exits. Every nonempty requested alternate result, including its diagnostics, uses a private 64 MiB session disk cache. Missing methods and actual helper/protocol errors remain retryable; unverified text survives partial class failures. Class/project changes cancel GUI source requests. A child guard kills/reaps the worker on every early exit. Input identity is checked after work before cache publication. No second parsed APK or idle helper remains loaded.

The worker has 30-second wall/CPU limits and 8 MiB output-file limits. macOS uses a sampled 512 MiB RSS kill threshold every 20 ms. Linux additionally enforces 1 GiB virtual-address/data limits. Sampling permits overshoot and can miss the peak of very short workers. Windows/other platforms currently fail closed with an explicit memory-enforcement diagnostic. Source-offset mapping uses memory proportional to requested methods, and normal disabled browsing retains the previous native render/cache path.

## Evaluation on 2026-11-14

The tested APK was `/Users/ch0pin/Desktop/BugBounty/mango-db/com.okx.money.apk`, SHA-256 `5bbbbbd5055140e6c735953fd05fb01dbe07ffb0843891c42f878a8c8cd47560`, containing 287,024 classes. The first bounded sample visited 44 app-owned classes and captured 16 native failures. A second sample visited 100 classes, excluded the first throw/rethrow reasons, and captured 12 failures. **Semantic correctness was not established for these 28 methods.** This historical evaluation records quality problems; available output is now displayed unverified instead of suppressed.

Observed backend problems included undeclared generated locals (`l1`, `i0_0`, `obj4`, `arr298`), Kotlin member names needing presentation rewriting, and constructors that redeclare parameters or compare an integer with null. These shapes are now diagnostics alongside the unverified output and exact original DEX. Independent `javac` checks confirmed the undeclared-variable and duplicate-parameter failures. Real constructor/string-overload output from the small D8 fixture compiled and ran successfully, establishing adapter/ID handling rather than an improvement over an existing native failure.

The accepted fixture's first cache-manager request took 34.1 ms and cached reuse took 0.27 ms. A separate kernel measurement of that helper invocation recorded 6.5 MiB maximum RSS. The realistic second sample recorded a 2.54 GiB host-process maximum RSS including rendering/substitution; sampled worker peaks were approximately 36–41 MiB, with sampled combined host/worker peaks up to 2.58 GiB. These measurements are separate from a strict combined allocation cap. One complex class took 29.3 seconds and completed inside the worker limit. The release helper is 3,715,344 bytes.
