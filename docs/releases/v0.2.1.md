RDX v0.2.1 (alpha) adds method call graphs and improves Java reconstruction and navigation.

### Changes

- Independent call-graph window with circular shaded nodes, pan/zoom, and highlighted paths to Android components. Default depth is 20, configurable up to 100.
- MCP `get_call_graph` with caller, callee, and bidirectional traversal, inherited-method alias resolution, structured nodes/edges and explicit limits.
- X-Refs prefer Java for unambiguous call locations; exact DEX remains available for ambiguous mappings.
- Java reconstruction now handles additional quiet-NaN constants and wide values in supported try/catch patterns.

Graphs describe static DEX calls, not runtime traces. Reflection, Intent routing and runtime virtual dispatch are not inferred. The GUI follows outgoing calls; caller/both direction selection is available through MCP.

Extract the archive fully. On macOS move `RDX.app` to Applications; on Windows
open `rdx.exe`; on Linux run `./rdx`. Archives include runtime instructions,
third-party notices and the optional source-statistics plugin. `SHA256SUMS`
contains the archive checksums. GitHub's automatic source archives are for developers.

### Requirements and known limits

No Java, Python, Rust or Android SDK is needed for the prebuilt apps.
macOS 13+, Windows 10+ x64, or Linux x64 with glibc 2.35+ and a graphical desktop
are required. Linux needs OpenGL/X11 or Wayland libraries and a desktop portal
for the file picker. Windows uses the static MSVC runtime.

macOS builds are ad-hoc signed but not notarized; Windows builds are unsigned.
First launch may require OS approval. See the [installation guide](https://github.com/Ch0pin/rdx/blob/v0.2.1/docs/install.md)
for platform instructions and MCP setup.

The native engine remains alpha: reconstruction coverage is incomplete and
unsupported methods are displayed as DEX disassembly. This is not a claim of
100% semantic accuracy. MCP's current tool set is documented [here](https://github.com/Ch0pin/rdx/blob/v0.2.1/docs/mcp.md).
