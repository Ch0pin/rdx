RDX v0.7.0 (alpha) reduces retained memory, expands native MCP analysis, and improves Java reconstruction and APK resource rendering.

### Changes

- Share the parsed project between the GUI and MCP service and reuse immutable source documents for navigation. Page inactive tab source to private files while preserving open tabs, selections, pins, and bookmarks. Coordinate optional cache retention and reserve estimated search-rendering memory before starting work.
- Expand native analysis with type and allocation references, integer and identifier searches, annotation usages, Kotlin metadata search, config-key consumers, merged-lambda case attribution, and structural networking candidates. Add reusable invoke indexing, cancellable call-graph batches, compact projections, constant-argument evidence, and source-reference resolution.
- Improve MCP recovery and query feedback with headless project recovery, instance-health diagnostics, convenient class/member selectors, source export, explicit incomplete-search feedback, and annotation-type absence warnings. Exact annotation lookups distinguish absent descriptors from present types with zero filtered usages.
- Inventory decoded resource XML, navigation routes, and Hotwire destination annotations with registration-array evidence. Improve manifest resource resolution, binary XML attribute recovery, launcher icon rendering, and horizontal scrolling in search results.
- Reconstruct additional constructor, loop, switch, initialization, and exception-control-flow patterns using control-flow and data-flow checks. Preserve explicit DEX fallbacks and reconstruction status when Java recovery cannot be established.

### Validation and scope

Local validation passed 2,431 enabled tests for the memory changes, followed by 110 MCP regression tests and a real-APK annotation diagnostic check. Formatting and strict all-target Clippy checks passed. The release workflow runs formatting, lint, tests, and executable smoke tests on all four release targets before publishing archives.

On a 24,663-class APK, three full-source search queries preserved exact results and offsets. Cold searches remained around 15 seconds and repeat searches took 22–127 ms; repeated no-match scans had before/after medians of 15.08/15.09 seconds. A separate 24-tab measurement reduced retained source heap from 192 MiB to 24 MiB while preserving every source byte. These measurements describe the tested workload, not a total process-memory ceiling or a guarantee for every APK.

Reconstruction coverage does not certify semantic equivalence. Inferred dispatch, networking, configuration, and navigation relationships carry their evidence and coverage boundaries. Annotation matching uses actual DEX descriptors; obfuscated semantic aliases are not inferred from shape alone.

### Requirements and limits

Prebuilt apps require no Rust, Java, Python, or Android SDK. Supported systems are macOS 13+, Windows 10+ x64, and Linux x64 with glibc 2.35+ and a graphical desktop. Linux needs OpenGL and X11 or Wayland libraries; the file picker uses a desktop portal.

macOS builds are ad-hoc signed and Windows builds are unsigned. See the [installation guide](https://github.com/Ch0pin/rdx/blob/v0.7.0/docs/install.md), [engine limitations](https://github.com/Ch0pin/rdx/blob/v0.7.0/docs/native-engine.md), and [MCP documentation](https://github.com/Ch0pin/rdx/blob/v0.7.0/docs/mcp.md).
